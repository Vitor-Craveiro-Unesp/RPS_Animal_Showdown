# Internationalization

Supported locales are `pt-BR`, `en`, and `zh-CN`, as required by [PROJECT_CORE.md](../PROJECT_CORE.md). The initial user-facing locale is a frontend decision; it must not remove or degrade the other two locales.

## Rules

- Keep UI messages in locale catalogs, keyed by meaning rather than rendered text.
- Components consume translated messages; they do not embed visible strings.
- Event and status messages must use translatable message identifiers plus structured parameters, not preformatted server text.
- Persist locale-neutral domain values (for example, `rock`, `paper`, `scissors`) and translate only at presentation boundaries.
- Validate all three locales when adding or changing a user-facing message.

Library selection and locale routing are deferred to the frontend owner; see [ADR-002](adr/ADR-002-i18n.md).
